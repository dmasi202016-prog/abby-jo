# 중소 유통업체 웹사이트 요구사항 문서 작성 계획

## 문서 목표

중소 유통업체(도매·소매·물류 유통)를 위한 웹사이트의 기능, 비기능 요구사항, UI/UX, 기술 요건을 마크다운(.md) 한 편의 요구사항서로 정리합니다.

---

## 요구사항서 권장 구조 및 내용

### 1. 문서 정보

- **문서명**: 중소 유통업체 웹사이트 요구사항 명세서
- **버전**, **작성일**, **대상 업체 규모** (예: 직원 10~50명, 연매출 구간)
- **용어 정의**: 유통, B2B, 재고, 발주 등 문서 내 용어 정리

### 2. 프로젝트 개요

- **목적**: 브랜드 노출, 제품 소개, 문의/발주 유도, 고객사 지원
- **타깃 사용자**: 기존 거래처, 신규 바이어, 내부 영업/관리자
- **핵심 가치**: 신뢰감, 제품/가격 정보 접근성, 문의 편의성

### 3. 기능 요구사항 (Functional Requirements)


| 구분    | 기능        | 상세 설명                         | 우선순위 |
| ----- | --------- | ----------------------------- | ---- |
| 회사 소개 | 회사/연혁/비전  | 회사 소개, 연혁, 비전·미션, 조직/오시는 길    | 필수   |
| 제품/상품 | 카탈로그·카테고리 | 제품 카테고리, 목록, 상세(이미지·규격·가격 정책) | 필수   |
| 제품/상품 | 검색·필터     | 상품명/코드/카테고리 검색, 필터(가격·규격 등)   | 권장   |
| 문의·발주 | 문의하기      | 연락처, 이메일, 간단 문의 폼(제품·수량·담당자)  | 필수   |
| 문의·발주 | 견적/발주 요청  | 견적 요청 폼, 발주 요청(선택)·이메일/알림 연동  | 권장   |
| 콘텐츠   | 뉴스/공지     | 공지사항, 보도자료, 이벤트(선택)           | 권장   |
| 콘텐츠   | FAQ       | 자주 묻는 질문(배송, 결제, 최소 주문 등)     | 권장   |
| 사용자   | 관리자       | 콘텐츠·제품·문의 관리, 간단 통계(선택)       | 필수   |
| 사용자   | 로그인(선택)   | 거래처 전용 로그인·주문 이력(Phase 2 등)   | 선택   |


- **우선순위**: 필수(1차 오픈) / 권장(1차 또는 2차) / 선택(추후)

### 4. 비기능 요구사항 (Non-Functional Requirements)

- **성능**: 메인·리스트 페이지 3초 이내 로딩, 동시 접속자 수 가정(예: 50명)
- **가용성**: 연간 99% 이상 목표(호스팅 계약에 명시)
- **보안**: HTTPS, 개인정보 수집 최소화, 문의/견적 데이터 암호화·접근 제한
- **호환성**: Chrome, Edge, Safari, 모바일 브라우저 지원, 반응형(모바일·태블릿·PC)
- **접근성**: WCAG 2.1 Level A 이상 권장, 키보드/스크린리더 기본 지원
- **언어**: 한국어 기본, 다국어는 추후 확장 옵션으로 명시

### 5. 화면/페이지 구성

- **퍼블릭**: 메인, 회사소개, 제품/카탈로그, 문의·견적·발주, 공지·뉴스, FAQ, 개인정보처리방침, 이용약관
- **관리자**: 로그인, 대시보드, 제품 CRUD, 문의/견적 목록·상세·상태 변경, 공지/FAQ 관리
- **와이어프레임/정보구조**: 페이지 수와 계층(1depth/2depth) 목록

### 6. UI/UX 요구사항

- **톤앤매너**: 업종에 맞는 신뢰감(깔끔·전문), 브랜드 컬러/로고 사용
- **반응형**: 모바일 우선 또는 PC·모바일 동등 고려, 터치·클릭 모두 고려
- **네비게이션**: 3클릭 이내 목표 페이지 도달, 명확한 CTA(문의하기·견적 요청)
- **폼**: 필수 입력 최소화, 에러 메시지·성공 안내 명확, 스팸 방지(캡차 등)

### 7. 데이터·연동

- **수집 데이터**: 문의(이름, 연락처, 회사명, 제품·수량·메모), 견적 요청 항목
- **저장·보관**: 개인정보 보관 기간, 파기 정책 명시
- **연동(선택)**: 이메일 발송(SMTP), 카카오 알림, ERP/재고 시스템(Phase 2)

### 8. 기술·구현 제약/가이드

- **기술 스택**: 제한 없음 또는 예시(정적 사이트/WordPress/React 등)
- **호스팅**: 국내 서버 권장(속도·개인정보), CDN·이미지 최적화 권장
- **도메인·이메일**: 회사 도메인 사용, 문의 수신 이메일 정책

### 9. 일정·단계(선택)

- **Phase 1**: 공개 페이지 + 문의/견적 + 관리자 기본
- **Phase 2**: 거래처 로그인, 주문 이력, 재고/ERP 연동 등

### 10. 산출물·승인

- 요구사항서(.md), 목업/와이어프레임, 최종 승인 일자

## 작성 시 유의사항

- 실제 작성 시에는 위 표를 마크다운 테이블로 변환하고, “우선순위”는 P0/P1/P2 등으로 통일 가능
- “대상 업체 규모·업종”(식자재, 의류, 전자부품 등)에 따라 “제품 카탈로그” 세부 항목을 구체화
- 관리자 기능은 “간단 CMS” 수준으로 범위를 제한해 초기 비용·일정 조절
